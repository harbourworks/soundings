# Changelog

All notable changes to soundings-cli. Versions follow [semantic versioning](https://semver.org); while it's 0.x, a minor version can change behaviour.

## 0.3.1 (25 November 2026)

Prompts sent to Gemini as a plain argument are traced, a project's own functions named like SDK calls are no longer reported as model calls, and `verify` catches a data-flow claim that cites only an SDK fact.

- **Gemini prompts passed on their own** are traced as prompts sent to Google AI: `model.generateContent(prompt)` and `model.generateContentStream(…)` in JavaScript/TypeScript, and `model.generate_content(prompt)` and `generate_content_async(…)` in Python, when the prompt is a variable, a template or f-string with something inserted, a joined string or a list. These are read only as a method on an object, and only in files that import Google's own SDK (`@google/generative-ai` or `@google/genai`; `google.generativeai` or `google.genai`). Before, a project that sent user text this way got a Google AI provider fact but no "Data sent to other services" entry. Fixed text such as `generateContent("ping")` is still not reported. In JavaScript, a property or a function call as the first argument (`generateContent(req.body.text)`) is not read yet.
- **A project's own function or class named like an SDK call** is no longer reported as sending prompts to an AI provider. A bare `generateText`, `streamText`, `generateObject`, `streamObject`, `embed` or `embedMany` now counts only when it is imported from `ai`, and a bare `new ConverseCommand(…)` or `new ConverseStreamCommand(…)` only when it is imported from `@aws-sdk/client-bedrock-runtime` or `@ai-sdk/amazon-bedrock`. Destructuring a `require` or an `await import()` of those modules without renaming still counts. A name defined in the file, imported from another module, or not imported at all no longer counts. In Python, a bare `generate_text(…)`, `generate_content(…)` or `generate_content_async(…)` counts only when that name is imported from the provider's SDK and the file doesn't define a function of the same name. Before, these could give a wrong high-confidence "Data sent to other services" fact.
- **`soundings verify`** fails a sentence that says data is sent to an AI provider ("sent to", "passed to", "shared with", "included in prompts" and the like, naming the provider as who receives it) when it cites only the fact that the provider's SDK is used and no data-flow fact for that provider (`flow-not-in-source`). It is not applied when the sentence also cites one of your answers, or says the data is not sent. A draft that passed before can now fail.

## 0.3.0 (21 November 2026)

Local models, AI routers and Django databases are recognised, more OpenAI calls are traced, and `verify` catches more uncited claims.

- **Ollama, LiteLLM and OpenRouter** are detected as AI providers: Ollama's client libraries in JavaScript/TypeScript (`ollama`, including `ollama/browser`) and Python (`ollama`, `langchain_ollama`), LiteLLM in Python (`litellm`), and OpenRouter in JavaScript/TypeScript (`@openrouter/sdk`, `@openrouter/ai-sdk-provider`). The Ollama fact says the scan can't tell where the Ollama server runs, and never says data stays local; it asks instead (`UQ-ollama-server-location`). The LiteLLM and OpenRouter facts say the vendors they route to aren't identified, and ask which ones (`UQ-litellm-routed-vendors`, `UQ-openrouter-routed-vendors`). Each also raises the usual data-use question. Prompts sent through Ollama's `chat` and `generate`, LiteLLM's `litellm.completion` and `litellm.acompletion`, and OpenRouter's `chat.send` are traced. `@openrouter/ai-sdk-provider` used with `generateText` or `streamText` is now reported as OpenRouter, not as "Vercel AI SDK". Not read yet: `completion` imported by name, LangChain's `ChatOllama` calls, embedding calls, the `ollama-ai-provider` package and LiteLLM's proxy configuration.
- **OpenAI structured-output and image calls** are traced as prompts sent to OpenAI: `responses.parse`, `chat.completions.parse`, `beta.chat.completions.parse`, `images.generate` and `images.edit`, when called on a client object (`client.images.generate(…)`). Before, a project using only these calls got an OpenAI provider fact but no "Data sent to other services" entry.
- **Django databases** are read from `DATABASES` in the project's settings. Django's own PostgreSQL (including PostGIS), SQLite (including SpatiaLite), MySQL and Oracle backends are reported at high confidence, cited to the `ENGINE` line. Comments, docstrings and test settings are ignored. When the engine can't be read (`env.db()`, `dj_database_url`, a variable or a third-party backend) but the project has Django models or migrations, the report says "SQL database (Django)" at medium confidence, so a Django project is no longer reported as "No database found". A found database raises its hosting and retention questions. Oracle is now recognised as a specific SQL engine.
- **`soundings verify`** warns on two more kinds of uncited sentence: one that puts a capitalised name the evidence doesn't mention where a vendor would go ("Payments are handled by PayPal"), and a sweeping negative about data ("No user content is ever sent to an AI provider"). These are warnings, so they fail the run only with `--strict`. The name LiteLLM is now checked too: a sentence that names it must cite a source that names it.
- **`soundings verify --strict`** now prints `Failed` when warnings fail the run. Before, it could print `Passed.` while exiting with 1. Exit codes are unchanged.
- The README's description of `verify` now says what it fails and what it only warns about.

## 0.2.1 (17 November 2026)

Prompts sent through renamed imports are now traced.

- **Aliased AI SDK calls and Bedrock commands** are traced as prompts sent to a model. `import { generateText as gt } from "ai"` makes `gt(…)` a model call, and `import { ConverseCommand as Conv } from "@aws-sdk/client-bedrock-runtime"` makes `new Conv(…)` one. Before, the provider was reported but the data sent to it was not. A renamed name counts only when it is imported from that SDK's own module and nothing in the surrounding code re-binds it (a parameter, a local variable, a function, a class or a `catch` parameter). A name that only looks like an AI function because of its alias, such as `import { tool as generateText } from "ai"`, is no longer counted as a model call. Aliases through `require` and names re-exported from another file are not followed yet.
- The README now says the scanner reads Python as well as JavaScript and TypeScript, and its sample report matches the current output.

## 0.2.0 (14 November 2026)

More AI providers and two ORMs recognised, so fewer projects come back as "No AI provider found" or "No database found" when the code says otherwise.

- **Mistral, Cohere, Groq and AWS Bedrock** are detected as AI providers, in JavaScript/TypeScript (`@mistralai/mistralai`, `cohere-ai`, `groq-sdk`, `@aws-sdk/client-bedrock-runtime` and their `@ai-sdk/*` packages) and Python (`mistralai`, `cohere`, `groq`, and the `langchain_mistralai`, `langchain_cohere` and `langchain_aws` packages). Each one found raises its own data-use question (`UQ-mistral-data-use` and so on).
- **Prompts sent to the new providers** are traced: Mistral's `chat.complete` and `chat.stream`, Cohere's client `chat` and `chatStream` (`chat_stream` in Python), Bedrock's `ConverseCommand` and `ConverseStreamCommand` (JavaScript), and Groq's OpenAI-style calls. A Bedrock client created with `boto3`, and prompts sent through LangChain's Bedrock wrapper, are not traced yet.
- **Prisma and Drizzle** are detected as data stores. Prisma's engine is read from the `datasource` provider in the `.prisma` schema (PostgreSQL, MySQL, SQLite, MongoDB, SQL Server or CockroachDB); Drizzle's from its `pg-core`, `mysql-core` or `sqlite-core` schema module. When the engine can't be read the report says "SQL database (Prisma)" or "SQL database (Drizzle)" at medium confidence. When an ORM and a database client point at the same engine, the report shows one fact listing both locations. A found store also raises its hosting and retention questions.
- **`soundings verify`** now also checks the names SQLite, SQL Server, CockroachDB and Bedrock: a sentence that names one of them must cite a source that names it too. Before, a sentence such as "We use SQLite" passed with any reference.
- **Licence:** `LICENSE` and `LICENSE-COMMERCIAL.md` now name the files covered by the Soundings Commercial Licence: `src/documents/build.ts`, the `src/import/` folder, seven named files in `src/export/` (the HTML, Word and questionnaire exports and the code that renders them), and the parts of `src/cli/main.ts` that run the paid commands and formats. Earlier text pointed at a `src/pro/` folder that doesn't exist. The scanner, questions, `verify` and everything else stay under the Functional Source License.
- The README now says the package is on npm.

## 0.1.0 (11 November 2026)

First release. A local scanner and document writer for security questionnaires: scan a JavaScript, TypeScript or Python project, answer only what the code cannot, and draft answers and documents where every statement points to a source.

- **Python support.** A built-in tokenizer (no parser dependency) lets the existing detectors read Python: AI SDKs and the prompts built from request data, FastAPI/Flask/Django sign-in, Microsoft Entra (MSAL), PostgreSQL, MySQL, MongoDB, Redis, SQLAlchemy, Azure Blob/Cosmos/AI Search and vector stores, `os.environ`/`getenv`/pydantic settings, and logged request bodies. Database connection strings in configuration are reported at medium confidence. Virtual environments and caches are skipped. A FastAPI fixture with an answer key and decoys covers it.
- **No false "not found" on mixed-language projects.** Found by scanning a real Python back end with a Next.js front end, which said "No database found". The scan now counts code it can't read and reports it at the top; with three or more such files it makes no "not found" claims and asks what that code does instead (`UQ-unanalysed-code`), and the question bank and documents use your answer.
- The same finding in several files is now one fact with several locations, not one fact per file.
- **`soundings document <type>`:** privacy notice, subprocessor list, DPIA draft, AI-use statement and trust page, built only from the scan and your answers (Pro). Gaps are listed as needing your input. Fixed legal-weight wording is isolated in one file and recognised by the verifier only on an exact match.
- **Exports:** Markdown, a self-contained HTML page (print it for a PDF) and a Word file with real footnotes, for documents and for `answers`. No new dependencies: the Word and ZIP writers are in the package.
- `soundings questions --documents` asks for what the documents still need.
- **Licensing with Polar:** `soundings buy`, `login`, `logout` and `status`. `answers` and `answer` need Soundings Pro (exit code 3 with a clear message otherwise); scanning, questions and verify stay free and never call the network. A saved check is trusted for 24 hours, a licence works offline for 14 days after its last check, `--offline` never calls, and `SOUNDINGS_LICENCE` serves CI without using a machine slot. Purchasing is open through Polar's hosted checkout.
- **`soundings verify`:** the claim validator. Checks any text against the evidence: every statement about the project needs a source that exists and mentions what the sentence mentions (services, numbers, places), absence and presence must agree with the cited fact, inferred facts must be worded as inferred, and wording that implies legal assurance is rejected. Local, no model.
- **`soundings answer <file.csv>`:** fills in a client questionnaire from the bank. Unclear rows are marked and listed, never guessed; filled cells are left alone; the original is never overwritten.
- **`soundings questions`:** asks only what the code can't answer (scan questions with stable IDs, plus profile questions about how your team runs), saves `soundings-answers.json`, and reuses answers across runs. `--set` for scripts; secrets are refused.
- **`soundings answers`:** answers a bank of 43 standard questions from evidence and your answers, as Markdown with numbered sources or as JSON. If your answer overrides the scan, the document says so.
- The scan now records qualified "not found" facts (no AI provider, database, sign-in, request-body logging or browser-exposed secret found), so an answer like "we don't use AI" has something honest to cite.
- **`soundings scan`:** a local scanner with 35 detectors for AI providers, data sent to them, third-party services, sign-in, data stores (with Supabase row-level security state), secret handling, request-body logging and browser exposure. It writes the evidence file and prints a plain-English report.
- Questions the code can't answer are raised with stable IDs (`UQ-supabase-region`).
- Optional `--seaworthy` report ingestion, linked to the facts each finding bears on.
- Self-scan in CI.
- Evidence schema 0.2 with content-derived IDs, scan coverage and a claim-marker parser.
- Redaction guard that fails on secret formats and on values from the project's `.env` files.
- Three fixture projects with answer keys, including decoys a scan must not report.
- CI: typecheck, tests and build on every pull request.
